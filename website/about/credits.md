# Credits

Muster's design was inspired by [atomic-claude](https://github.com/damusix/atomic-claude) ([site](https://atomic.alonso.network/)), [superpowers](https://github.com/obra/superpowers), and [gsd-core](https://github.com/open-gsd/gsd-core). It vendors a curated set of MIT-licensed skills and agents, and every skill, agent, command, output style and pipeline that is based on an external repository or work (an article, book, paper, standard, talk or person) says which one in its own `upstream:` field.

## How provenance is recorded

[`vendor/manifest.yaml`](https://github.com/Adnova-Group/muster/blob/main/vendor/manifest.yaml) is the single source of truth. Each item's `upstream:` field, the catalog provenance summary, and [NOTICE](https://github.com/Adnova-Group/muster/blob/main/NOTICE) (with each upstream's copyright line) are generated from it by `muster provenance --write`, and the test suite fails when any of them drift. An item with `upstream: []` is Muster-authored. A repository entry names the repository, the pinned commit, the upstream path, the license, and the relation; a work entry names its kind, title, author and link. An origin Muster's history mentions but never names is recorded as `unknown` with a dated note saying what was searched. Relations:

| Relation | Meaning |
| --- | --- |
| vendored | upstream text carried essentially unchanged |
| adapted | upstream text edited |
| mechanism-port | a mechanism re-implemented in new text |
| inspired-by | an idea, structure, or framework named; no text carried over |

A work is always inspired-by: Muster takes ideas, frameworks or structure from it, never its text.

The Codex plugin carries the same record as `NOTICE` and `PROVENANCE.md`, since Codex skill headers cannot hold the field.

## License review

Some sources carry no license, a NonCommercial or NoDerivatives license, or a proprietary one, so Muster has no right to reuse their text. Each was compared with the Muster items based on it, and the manifest records the result as a `licenseReview`: `ideas-only` when no text was carried, or `clean-room-rewrite` when Muster text that followed the source too closely was rewritten from the underlying idea (on 2026-11-09: the humanizer's vocabulary lists, the PRD section structure, the epic hypothesis template, and five quotations in the audit hunt lists, now paraphrased with their links kept). The test suite fails on any such source without a review, and on any waiver still pending a decision.

## Upstream routing on Codex

On Codex, Muster prefers an enabled authoritative upstream implementation over its own copy whenever one exists: the official [Superpowers](https://github.com/obra/superpowers) plugin, [wshobson](https://github.com/wshobson/agents)'s per-plugin Codex skills, and GSD's installer-generated Codex skills.

The bundled `sp-*`, `wsh-*`, and `muster-gsd-*` skills are deterministic **fallbacks**: they keep every role resolvable when an upstream is absent, and they never implicitly install those providers on your behalf. The pinned compatibility survey — which upstreams were checked, at which refs, including Atomic Codex, Book Genesis, the humanizer sources, and Promptfoo — is recorded in [`codex/upstreams.json`](https://github.com/Adnova-Group/muster/blob/main/codex/upstreams.json).

## Clean-room specialists

Alongside the vendored material, Muster ships its own specialists in `plugin/agents/`, authored fresh from atomic-claude's role concept:

- **muster-surgeon**: precise 1-2 file edits
- **muster-investigator**: read-only locator
- **muster-strategist**: heavyweight reasoning
- **muster-improver**: read-only post-run retrospective that proposes self-improvement edits

The `muster-runner` agent (built from the lifecycle mechanisms credited above) left the Claude plugin in revival stage 2b. It survives only as the frozen Codex lane's production-wave policy, in `codex/frozen/agents/muster-runner.md`.

## Lifecycle seats adapted from GSD

The stage-2 lifecycle agents are adapted from [gsd-core](https://github.com/open-gsd/gsd-core) v1.20.1 agents (MIT). gsd's measured protocol text (honest abstain, the evidence gate, revision-loop limits, failing direction, the must-NOT probe, deviation rules, the self-check and the destructive-git ban) is carried verbatim in marked regions; `muster vendor update gsd` keeps them in sync by 3-way merge:

- **muster-planner**: writes the run's PLAN.md (from gsd-planner)
- **muster-plan-checker**: checks PLAN.md before execution (from gsd-plan-checker)
- **muster-executor**: implements one task in its own worktree (from gsd-executor, with the former builder's one-slice scope contract)
- **muster-verifier**: goal-backward verification with honest abstain (from gsd-verifier)
- **muster-reviewer**: adversarial review of one task's commits (from gsd-code-reviewer, with muster's verdict discipline)

## Additional inspiration (clean-room, mechanism-level)

A cluster of systems introduced in 0.5.0 -- the sprint coordination protocol (claim/receipt/ledger discipline), the citation-guard gate, QA runbook memory, the voice/audience/brand profile system, newsletter signal-diff, the assumption checker, and the document-ingestion contract -- were designed with mechanism-level inspiration from Nate B. Jones's Unlock AI open-skills/open-engine patterns ([unlock-ai.natebjones.com](https://unlock-ai.natebjones.com)). No code, prose, or configuration was copied; Muster's implementations are original, adapted to its own deterministic-CLI/model-facing-skill architecture. The Unlock AI library is members-only, so this could not be checked against its text; the items it informed are listed under Works above.
