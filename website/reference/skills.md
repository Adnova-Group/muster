# Skill library

Muster bundles a library of skills in `plugin/builtins/`. They stay out of Claude Code's skill listing, so they cost nothing until a task uses them. The planner binds them to tasks by id (the `skills` attribute in `PLAN.md`), and the builder reads each bound `SKILL.md` by path before it works.

Use `/muster:skills` (or the `muster skills` CLI) to browse and opt in:

| Verb | What it does |
| --- | --- |
| `list [domain]` | Builtins grouped by catalog role, with upstream and license. |
| `show <id>` | Description, source, license, catalog roles, file path, and whether this project enabled or pinned it. |
| `search <query>` | Builtins first, then the [ui-skills.com](https://www.ui-skills.com/) registry. The registry is fetched only on search, with a 5-second timeout, and cached for 24 hours in the user cache directory. Offline, you get builtin results and a note. |
| `enable <id>` | Copy a builtin into this project's `.claude/skills/<id>/`, so Claude Code offers it natively in this project only. The copy keeps its license and upstream, and it never overwrites an existing directory. |
| `disable <id>` | Remove the files `enable` or `add` wrote, as listed in `.claude/skills/.muster-enabled.json`, and only while they are unmodified. |
| `add <publisher>/<skill>` | Install a registry skill into `.claude/skills/<skill>/`. It checks the publisher repository's license through the GitHub API first and refuses repositories with no license, NonCommercial, NoDerivatives or proprietary terms. |
| `pin <id> [--role <role>]` / `unpin <id>` | Project pins in `.muster/config` (see [Configuration](./configuration#project-config-muster-config)). Build-args binds a pinned skill to every matching task. |
| `usage` | Which skills the runs in `.muster/runs/` bound, applied, missed or never used. |

When no builtin matches an outcome strongly, `preflight` may suggest up to three registry skills from the cached registry. It never fetches during preflight. Each suggestion is marked as not installed.

Builtins are grouped by their first catalog role. A builtin with no catalog entry is listed as `unrouted`: workflows read it by path, but the planner never binds it.
